### 1차선 이탈 원인
- 경로 추정은 정확: 제어기 평가 지점에서 코너 평균 오차 2 cm 이내 (점선만 보이는 프레임 포함)
- 평가 지점 0.36 = 뒷축 앞 약 1.45 m. 반경 1.5~2.4 m 1차선 코너에서 차 전체가 가운데보다 8~20 cm 안쪽. 1차선 바퀴 여유는 한쪽 약 12 cm
- 가제보는 YOLO 가 점선을 잘 잡음. 실제 트랙에서 90° 코너 점선을 더 자주 놓친다면 경로가 튀는 문제도 있을 수 있고, 그때는 바깥 실선 기준이 더 도움될 것

### 장애물
- 차선 판정(`lane_of`) 대부분 맞음. 틀린 것은 장애물이 1.4 m 안으로 붙었을 때, 차선 변경 직후 차가 아직 옛 차선에 걸쳐 있을 때
- 팀 라벨 사진 40장에도 `lane_of` 를 그대로 돌림: 앞 4 m 안 차 대부분 맞음, 좌커브 1.35 m 앞 내 차선 차 1건 판단 못 함(None)
- 감지 2 m 는 차선 변경(2 s)이 끝나기 전에 닿음. 배치 A/B 첫 장애물이 커브 안이라 더 불리
- 배치 A 첫 장애물은 횡단보도 바로 뒤라, 신호등 앞에서 이미 보여 차선 변경이 먼저 시작됨 → 빨간불에 서 있는 동안 (시간 기준) 변경이 혼자 끝나고 → 출발할 때 차는 옛 차선인데 규칙은 새 차선 → 그 차를 내 차선으로 다시 보고 되돌아와 충돌. 수정 2, 3 이 이것을 막음
- 남은 실패: 커브 안에서 차선을 바꿀 때 새 차선을 지나쳐 실선을 넘음 (B 셋째 장애물 앞 좌커브에서 2차선으로, B 둘째 앞 S자에서 1차선으로). 가제보 조향은 실차보다 느리고 덜 꺾여(명령의 0.57~0.73) 실차에서 다를 수 있음 → 실차에서 `lane_change_sec`, `lane_change_pwm`, 감지 거리로 맞출 것
- `lane_change_pwm` 180 은 가제보에서 뚜렷한 개선 없음 (성공 1/4)
- 가제보 조향 반응이 실차보다 느림 (10/31 측정, 차선 변경이 명령 시간의 약 2배) → 충돌은 실차보다 비관적일 수 있음

## 영상 보는 법
- 순서: 소개 → 2차선 → 1차선 지금 설정(문제 재현) → 1차선 개선 → 바깥 실선 기준 → 신호등 → 장애물 2 m (main) → 미션1 흐름 (신호등 + 장애물, 이 브랜치) → 정리

## 실차에서 확인할 것
1. 카메라 렌즈 ~ 뒷바퀴 축 수평 거리 (가제보 가정 0.246 m)
2. 1차선: 슬라이더 "1차선 평가 지점" 0.1 (안쪽에 붙으면 더 작게, 흔들리면 0.2 쪽). 2차선은 "평가 지점" 0.36 그대로
3. 1차선 코너에서 path_viewer 빨간 경로가 튀면 점선 인식 문제 → "1차선 바깥 실선 기준" 1 로 비교
4. 장애물: 감지 거리 2 m 에서 늦으면 3 m. 실제 차선 변경에 걸리는 시간과 거리, 커브 안에서 넘치면 `lane_change_sec` 늘리기 또는 `lane_change_pwm` 으로 감속. 신호 정지 중에 차선 변경이 멈추는지 (tune_gui 상태 줄)
5. 횡단보도 줄무늬 실제 길이 (사진 추정 1.1~1.2 m, 가제보 1.0 m) → 정지 위치에 영향
