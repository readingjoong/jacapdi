## 알게 된 것

### 1차선 이탈 원인 = 앞보기
- 경로 추정은 정확: 제어기 평가점(x 0.36)에서 코너 평균 오차 2 cm 이내 (점선안, 바깥 실선안 둘 다)
- 차는 코너에서 1차선 가운데보다 8~20 cm 안쪽. 평가점이 뒷축 앞 약 1.45 m 라 반경 1.5~2.4 m 코너를 질러감. 1차선 바퀴 여유는 한쪽 약 12 cm
- 앞보기별 (가제보, 1~6회)

| `front_axle_offset_m` | 2차선 이탈 0 | 1차선 이탈 0 (점선안 / 바깥 실선안) | 1차선 실선 밟는 시간 평균 (점선안 / 바깥 실선안) |
|---|---|---|---|
| 0.36 (지금) | 4/4 | 1/6 / 0/3 | 15.5 / 15.1 s |
| 0.2 | 2/2 | 1/1 / 1/1 | 12.0 / 9.0 s |
| 0.1 | 2/3 (1회 왼쪽 위 코너 바깥 이탈) | 3/3 / 3/3 | 2.2 / 0.5 s |

### 바깥 실선 기준 (팀원 제안)
- `lane1_outer.patch`: 1차선에서 점선 대신 2차선 바깥 실선 안쪽 끝에서 수직 1.325 m (0.85 + 점선 0.05 + 0.425) 안쪽 곡선을 가운데로. 안쪽 실선이 보이면 안쪽 실선 우선, 두 실선 다 없으면 원래 계산
- 켜기: tune.json 에 `"lane1_ref": "outer"` (없거나 "dashed" 면 원래 동작). 2차선 계산은 그대로
- 효과: 코너 먼 쪽 경로 치우침 6 cm → 1~3 cm, 실선 밟는 시간 조금 줄어듦. 가제보는 YOLO 가 점선을 잘 잡으므로 실제 트랙에서 점선을 더 놓친다면 효과가 더 클 수 있음
- 적용: `git apply docs/gazebo_1105/lane1_outer.patch` (main 0a35a05 의 `nodes/lane_path_node.py` 기준, 확인함)

### 장애물
- 차선 판정(`lane_of`) 12번 중 10번 맞음. 틀린 2번은 장애물이 1.4 m 안으로 붙었을 때, 또는 차선 변경이 끝났다고 본 직후 차가 아직 옛 차선에 걸쳐 있을 때
- 팀 라벨 사진에 `lane_of` 를 그대로 돌려 봄: 앞 4 m 안 차 대부분 맞음, 좌커브 1.35 m 앞 내 차선 차 1건 판단 못 함(None)
- 감지 2 m: 차선 변경(2 s)이 끝나기 전에 닿음. 배치 A/B 첫 장애물이 커브 안이라 더 불리
- 가제보 조향 반응이 실차보다 느림 (10/31 측정, 차선 변경이 명령 시간의 약 2배) → 충돌 결과는 실차보다 비관적일 수 있음

### 신호등
- 빨강 또는 노랑 감지 + 횡단보도 먼 끝 1.39~1.49 m 에서 정지 명령, 앞범퍼가 정지선과 횡단보도 사이(횡단보도 3~15 cm 앞)에 섬
- 가로형 신호등이 도로 위에 있어 1, 2차선 모두 정지 자리에서 보임

## 실차에서 확인할 것
1. 카메라 렌즈 ~ 뒷바퀴 축 수평 거리 (가제보 가정 0.246 m)
2. 1차선 `front_axle_offset_m` 0.2 → 0.1 (tune_gui 슬라이더), 2차선은 0.36. 코너 안쪽 붙음과 직선 흔들림 확인
3. 장애물: `obstacle_dist_m` 3.0, 실제 차선 변경에 걸리는 시간과 거리
4. 횡단보도 줄무늬 실제 길이 (사진 추정 1.1~1.2 m, 가제보 1.0 m), 횡단보도 뒤 얇은 선 → 정지 위치에 영향
